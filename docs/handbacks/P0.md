## 1. What was built

### The API contract — `docs/openapi.yaml`
Four read-only endpoints under `/api/pathfinder/*`, exactly as the brief specifies:

| Endpoint | What it serves |
|---|---|
| `GET /api/pathfinder/loop` | The live loop **as a story** — six beats (noticed → hypothesis → experiment → outcome → learning → next) plus the deterministic `facts[]` every sentence references, the trigger that woke the LLM, pipeline counts by status, and today's real token spend against the daily cap. |
| `GET /api/pathfinder/experiments?status=` | id · hypothesis · status · `historical_return` · `virtual_return` · occurrences · n · spark · as_of. Ordered **losers first** (died leads, promoted last). |
| `GET /api/pathfinder/experiment/{id}` | The full journey: question, rulebook, story, facts, evidence bundles, virtual book with its losers-first ledger, the **append-only L1–L3 change-log**, triggers, LLM usage, and the post-mortem when it died. |
| `GET /api/pathfinder/learnings` | `learned[]` (statement, level, confidence, n, which experiments and evidence produced it, which strategy versions it changed) + `testing_next[]` (question, why now, the deterministic test planned, and **what is blocked and why**). |

The spec is **generated from Pydantic models**, not hand-written (ADR 0003), and **merged** into
`docs/openapi.yaml` so session 01's `/api/trader/*` and every later slice can share the file.
4 paths, 38 component schemas, all `$ref`s resolving.

### The contract as code — `backend/pathfinder/schemas.py`
The product laws are Pydantic validators, so a dishonest payload cannot be constructed:

- expectancy required, `win_rate_pct` optional — expectancy is the hero;
- `max_drawdown_pct` + `current_drawdown_pct` required — no return without its drawdown;
- **no** target / projection / expected-return field exists anywhere;
- `Provenance` (source + window + `as_of` + cost convention + the deterministic component that
  computed it) required on every `Fact` and every `PerformanceBlock`;
- `sample_flag` **derived** from n (greyed <20, flagged <50) so no client re-implements the rule;
- `ledger_losers_first` validated ascending by net P&L;
- entry must be the next session after the signal bar;
- **LLM-authored prose may not contain a numeral** — numbers are `{{fact:fct_…}}` references (ADR 0002);
- L4 change-log entries must be human-decided and human-approved; L3 must state its validation.

### The honest mock — `backend/pathfinder/mock_app.py` + `fixture_data.py`
**6 experiments, one per lifecycle status**, incl. `exp_0007` **died-with-post-mortem**. Deliberately
unflattering, because that is what will ship:

| Experiment | Status | Historical expectancy (2× slip) | Forward virtual (2× slip) | n | flag |
|---|---|---|---|---|---|
| `exp_0007` gap-up continuation | **died** | 0.24 (**−0.03**) | −0.11 (−0.29), −12.7% DD | 48 | flagged |
| `exp_0014` gap-fill by 10:15 | testing | 0.12 (**−0.01**) | −0.06 (−0.22) | 11 | **greyed** |
| `exp_0009` thin-volume high close | validating | 0.22 (0.09) | 0.05 (**−0.04**) | 27 | flagged |
| `exp_0015` breadth divergence | queued | — | — | — | unknown |
| `exp_0011` refuses a new low | promising | 0.27 (0.14) | 0.21 (0.08) | 34 | flagged |
| `exp_0003` pullback on dry volume | promoted | 0.31 (0.19) | 0.18 (0.06), −5.1% current DD | 61 | ok |

Two of six fail the 2× slippage gate. Forward is weaker than history in every case that has both.
One greyed sample, three flagged. The dead one's post-mortem carries **what we kept** — "a gap is a
liquidity event, not a direction event" — which then appears in `/learnings` as a live constraint on
new intraday hypotheses. That chain (fail → learn → change the gate) is the product.

### The Postgres authoritative schema — `migrations/0001_pathfinder.sql` + `docs/DATA_MODEL.md`
The nine locked tables (`experiments`, `hypotheses`, `parameters`, `trades`, `outcomes`, `evidence`,
`strategy_versions`, `learning_events`, `decisions`) plus the supporting tables the API needs
(`constitution_versions`, `facts`, `story_lines`, `triggers`, `llm_calls`, `post_mortems`,
`experiment_state`, `research_cycles`) and `recall_embeddings` for pgvector.

**The laws are in the DDL, not just in code:** `deny_mutation()` makes UPDATE/DELETE raise on all 17
history tables; hash chains on the published record; `CHECK (range_end <= as_of)` for point-in-time;
`CHECK (entry_date > signal_date)`; a rulebook cannot contain a target price; L4 cannot be authored
by a non-human; L3 cannot replace without stating validation; L2 cannot move a parameter outside its
approved range; and a CHECK that LLM-authored prose contains no digit once fact tokens are stripped.

### The `pathfinder_llm` gateway contract — `docs/STRATEGY_METHODOLOGY.md` §3 + `backend/pathfinder/llm/gateway.py`
`reason()` / `narrate()` / `classify()` signatures; the locked job→model routing
(Sonnet 5 for hypothesis/critique/decide-next, Haiku 4.5 for narrate/classify, Opus 5 rarely); the
three versioned structured-output schemas in full JSON Schema (`pathfinder.reason.v1` cannot express
`L4`; `pathfinder.narrate.v1` gives `headline` the pattern `^[^0-9]*$`); the prompt-caching prefix
layout with its silent-invalidator rules; the batch policy; the hard daily cap enforced against
**IST**; and provider independence. **P0 ships the Protocol only — no provider, no SDK import.**

`docs/STRATEGY_METHODOLOGY.md` §1 also writes down the shared quant law (marking convention, costs +
2× slippage, expectancy-decides, strategy-replay-not-hold-to-close, discovery vs OOS, the go/no-go
gauntlet) once, so no later session re-derives it.

## 2. How to run it

```bash
cd backend && uvicorn pathfinder.mock_app:app --port 8010
```

Then `http://127.0.0.1:8010/docs` · `/api/pathfinder/loop` · `/api/pathfinder/experiments?status=died`
· `/api/pathfinder/experiment/exp_0007` · `/api/pathfinder/learnings`.

**Session P2 points `EXPO_PUBLIC_API_BASE_URL` at that server.** When P1 lands, the base URL changes
and nothing else does.

```bash
python -m pytest backend/tests/test_pathfinder_p0.py -q   # the guardrail suite
python scripts/gen_openapi.py                              # regenerate spec + JSON fixtures
python scripts/gen_openapi.py --check                      # fail if the spec is stale
python scripts/validate_openapi.py                         # validate the contract
```

Raw JSON snapshots of every response are in `backend/pathfinder/fixtures/*.json` (~190 KB, 15 files)
for anyone who prefers Prism/MSW to running the FastAPI mock.

The router is also mounted in `backend/main.py`, **default OFF**
(`KANIDA_PATHFINDER_ENABLED`, verified both ways). Mock research must not be reachable from the live
product surface by accident. `KANIDA_PATHFINDER_SOURCE=postgres` **raises** until P1 lands rather
than silently serving fixtures as engine output.

## 5. Risks

1. **The DDL has never been executed.** No reachable Postgres in this session — the local PG 18
   instance needs a password I will not supply, and I would not run a migration against the AWS
   instance from here. `migrations/0001_pathfinder.sql` is written carefully but is **unverified**.
   *First action for P1:*
   ```bash
   psql "$KANIDA_PG_URL_SCRATCH" -v ON_ERROR_STOP=1 -f migrations/0001_pathfinder.sql
   ```
   against an empty scratch database, then add the missing test rows named in
   `docs/TEST_PLAN.md` § "Known gap for P1" (each CHECK must reject the row it exists to reject).
   Two constructs I would look at first: the `?|` jsonb operator inside a CHECK (fine via `psql -f`,
   but some drivers treat `?` as a parameter placeholder), and `CREATE EXTENSION` inside the guarded
   `DO` block.

2. **`openapi-spec-validator` is not installed here**, so "the spec validates" means: FastAPI emitted
   a 3.1 document, and `scripts/validate_openapi.py`'s own structural + product-law checks pass (all
   `$ref`s resolve, no orphan schemas, every operation carries 200/400/404/500, no banned fields,
   `PerformanceBlock` requires expectancy and both drawdowns). Run
   `pip install openapi-spec-validator` and re-run the script for the full third-party validation —
   it is wired in and will run automatically once present.

3. **The fixtures are invented, and they look real.** That is the point and also the danger. Three
   defences are in place: the mock's `/` returns a `warning` field saying so, every payload carries
   its honesty label, and `KANIDA_PATHFINDER_SOURCE=postgres` raises rather than falling back. Do not
   weaken the third one.

4. **`{{fact:…}}` resolution is now the frontend's job.** P2 must render tokens against `facts[]`
   (and show n / window / source on the number). If P2 renders the raw string, customers see
   `{{fact:fct_e3_virt_exp}}`. Flagged into the P2 brief below.

5. **Supporting tables beyond the locked nine.** `facts`, `story_lines`, `triggers`, `llm_calls`,
   `post_mortems`, `experiment_state`, `constitution_versions`, `research_cycles` were added because
   the API cannot be served without them. Reasonable, but it is an expansion of what you locked —
   flagging it rather than burying it.

6. **Six fixtures, not the 4–5 the brief asked for.** One per lifecycle status, so P2 can build every
   state. Say the word and I will trim.

7. **`docs/openapi.yaml` is generated.** Anyone hand-editing it will have their change reverted by
   the next `gen_openapi.py` run. Contract changes go in `backend/pathfinder/schemas.py`. Guarded by
   test P0-36, but worth saying to the next session out loud.
