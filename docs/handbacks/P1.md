# Hand-back — Session P1: Pathfinder, the real loop

**Date:** 2026-09-09 (IST) · **Branch:** `feat/product-build` · **Brief:** `docs/sessions/PATHFINDER.md` § Session P1
**Status:** done to the brief's "done when", **after** an adversarial quant audit that found four
things wrong and sent me back to fix them. **Nothing committed** — the tree is left for your review.

> **The headline, so it is not buried.** The loop ran end to end on real point-in-time data and
> **opened four experiments. All four died. Nothing was promoted.** That is not a failure of the
> session; it is the session working. The one that went the whole way — Observe → Question → Test →
> Interpret → Virtual Trade → Track → Review → Learn → Next — cleared discovery, cleared
> out-of-sample, and then **lost 15.8% of virtual capital with a 27.7% drawdown** in the sealed
> forward window. It is published with its post-mortem, and it is the most useful thing here.
>
> **The second headline is about the engine, not the market.** `dev-quant-auditor` found that the
> loop's own most interesting claim was wrong, that its significance test was mis-specified in the
> flattering direction, and that its survivorship disclosure described a population it does not use.
> All three are fixed, and the fixes changed the results. §5 is the honest account.

## 1. What was built

### The deterministic engine — `backend/pathfinder/engine/`

Ported from `Kanida_Falcon` rather than rebuilt, as the brief required:
`scripts/agent_arena.py` (the canonical *WHEN trigger → outcome over horizon vs baseline after
costs* hypothesis, its trigger primitives, market worlds, the edge-vs-baseline framing),
`arena/arena.py` (`sim_trade`'s entry/stop/target/horizon marking, the constitutional-score idea,
the a-priori point-in-time selection discipline), and `scripts/mine_phase1.py` (train→validate→
promote-only-if-it-holds, lift over a base rate, the leaf-rule grid).

| Module | What it owns |
|---|---|
| `market.py` | **The point-in-time seal.** Wide OHLCV frames built with a hard `as_of`; a look-ahead bug is a `KeyError`, not a quietly better number. `expanding_percentile` ranks a reading only against sessions strictly before it. |
| `hypothesis.py` | The **closed** primitive library (12 triggers × 5 regime contexts) and `HypothesisSpec.parse`, where a model's proposal becomes testable — or is rejected, never clamped. |
| `replay.py` | `ExitGrid`: the whole strategy replayed **once**, vectorised, so the signal set, the baseline and the placebo are measured by identical code. Entry = next open. Same-session stop-and-target resolves as the **stop**. A gap through the stop fills at the **open**. Plus `block_placebo` and `cluster_robust_t` — the two statistics the audit forced. |
| `evidence.py` | Expectancy, the 2× slippage variant, drawdowns in exit order, provenance, the cost ladder. The only producer of a `PerformanceBlock`. |
| `book.py` | The **virtual book**: ₹10 lakh, ten slots, one position per symbol, no leverage, marked to the close every session — with `selection_rule` as a *named, measured* parameter. |
| `observe.py` | The cheap continuous observer, the unusual-condition triggers, and the **pre-registered** 288-candidate grid scanned on the discovery window only. |
| `governance.py` | The Constitution reader (there is deliberately no writer), the gauntlet, the implementability gate, the L1–L4 change-log types, and the fatal/advisory split that decides what kills versus what only blocks promotion. |
| `loop.py` | The orchestrator. `_wake` is the only door to a model and it **refuses to open without a trigger**. |
| `repository.py` | Append-only, hash-chained persistence, dialect-portable between SQLite and Postgres, thread-local connections. |
| `recall.py` | pgvector-shaped associative recall. Never evidence — only a pointer back to an authoritative row. |

### The `pathfinder_llm` gateway — `backend/pathfinder/llm/`

`AnthropicProvider` is the **only file in Pathfinder that imports a model SDK**: structured outputs
via `output_config.format` with `strict: true`, adaptive thinking on Sonnet/Opus and budgeted
thinking on Haiku, cache breakpoints after the Constitution and after the fact table, `stop_reason`
checked before content is read. `RecordedProvider` replays cassettes. `NullProvider` raises. All
three go through the **same** `contracts.py` enforcement, and `budget.py` checks the hard daily cap
against **IST** *before* every call.

### Governance — `config/pathfinder_constitution.yaml`

The blocker P0 named. Risk limits, honesty rules, compliance boundaries, permitted actions, the
L1–L4 hierarchy, the gauntlet bars, the LLM budget and routing, and the **approved parameter ranges**
L2 is checked against. It is an **UNSIGNED DRAFT**, and while `approved_by` says so the engine
**refuses to promote anything**. Enforced in code, asserted by a test.

### Persistence, and serving the real data

`migrations/0002_pathfinder_sqlite.sql` is a faithful SQLite mirror of `0001_pathfinder.sql` — same
tables, same columns, same laws — because P1 had no reachable Postgres either (§5.5) and the loop
had to be *verifiable* today. `backend/pathfinder/store_engine.py` then serves the P0 contract from
it: **the router, the Pydantic schemas and P0's 37 tests did not change**, and they now pass against
engine output, which was the acceptance bar P0 set.

## 2. How to run it

```bash
python scripts/run_pathfinder_loop.py --fresh --llm recorded
```

~7 minutes: loads 2.6M daily bars, scans 288 candidates, opens and judges up to six experiments,
writes `var/pathfinder.db`. `--llm none` runs it with no model at all (every beat engine-authored,
visibly); `--llm live` uses Claude once `ANTHROPIC_API_KEY` is set.

```bash
python -m pytest backend/tests/test_pathfinder_p1.py backend/tests/test_pathfinder_p0.py -q
```

Serve it:

```bash
cd backend && KANIDA_PATHFINDER_SOURCE=engine uvicorn pathfinder.mock_app:app --port 8010
```

**P2 needs no code change** — only `KANIDA_PATHFINDER_SOURCE=engine` on the server it already points at.

## 3. Results / evidence

### 3.1 The suite

**97 passed** — P0's 37 rows (unchanged, now against engine output) + **60 P1 rows**
(`docs/TEST_PLAN.md` P1-01…P1-60). Rows P1-46…P1-60 assert the honesty rules on the **real run
database**, not on anything hand-written. Rows P1-35…P1-45 close the gap P0 flagged: every
product-law CHECK now has a test proving it rejects the row it exists to reject.

### 3.2 What the loop found

288 candidates screened on 2016-01-01…2021-12-31 (discovery), judged on 2022-01-01…2024-06-30
(out-of-sample), traded on 2024-07-01…2026-07-29 — a window **sealed when the experiment opened**.
Costs `costs_v3.1_cnc_delivery` (22.2bps statutory + 20bps slippage round trip). Losers first:

| Experiment | Rule | Discovery exp (2×) | Out-of-sample exp (2×) | Virtual book | Died of |
|---|---|---|---|---|---|
| `exp_0001` | gap **down** ≥3%, index below 200DMA, **short**, 10 sessions | **+2.61** (+2.41), edge +3.89, n=2,469 | — | — | **not implementable** |
| `exp_0002` | volume dry-up 5×0.6, index below 200DMA, long, 10 sessions | +2.62 (+2.42), edge +2.00, n=385 | **−1.62** (−1.82), edge −1.68, n=243 | — | edge did not persist OOS |
| `exp_0003` | gap **up** ≥3%, index below 200DMA, long, 10 sessions | +2.25 (+2.05), edge +1.63, n=1,840 | **+0.79** (+0.59), edge +0.74, n=524 | **−15.8% on capital, 27.7% max DD, −0.86/trade**, n=184 | no edge after costs |
| `exp_0005` | 3 inside bars, index above 200DMA, long, 10 sessions | +0.96 (+0.76), edge +1.04, n=342 | +1.15 (+0.95), edge +0.72, n=174 | **−8.5% on capital, 12.3% max DD, −0.83/trade**, n=103 | no edge after costs |

(`exp_0004` and `exp_0006` were skipped as duplicates of ideas already open — the same trigger in a
different exit structure.)

Three findings are worth your time:

**(a) The single strongest edge in the entire scan is not a product.** `exp_0001` — shorting a 3%+
gap-down in a falling market — returned **+2.61% per trade net of costs, +3.89 over its own
universe, across 2,469 trades.** It is also a *ten-session short in the NSE cash segment*, which a retail customer cannot
hold: it would need stock futures — different universe, costs, lot sizes, roll. Killed on that basis
alone and published with a post-mortem. **Implementability now screens before ranking.**

**(b) A rule is not a book — and the reason is structural, not a tie-break.** `exp_0003` did
everything right: positive in discovery, positive at 2× slippage, still positive out of sample on
data that had no say in choosing it. Then the book lost money. The unconstrained rule made **+4.42%
per trade** over the same sealed window while the book made **−0.86%**. The engine's *first*
explanation was the tie-break used when more signals fire than there are slots — and that
explanation was wrong. Measured: the spread across every approved selection rule is **0.20pp, 3.7%
of the 5.28pp gap**. The real cause is that **47% of the rule's trades arrive on its three busiest
sessions**, and removing those days drops the rule's expectancy from **+4.42 to +0.46**. A ten-slot
book is structurally unable to be in a session that fires three hundred signals at once. All of that
is now computed, published as facts, and said in the narrative.

**(c) Significance, measured properly, is the thing none of them have.** With a null that respects
how these signals actually arrive — in clusters, on market-wide event days — `exp_0003`'s
out-of-sample t is **1.11 on 81 independent sessions**, not the 1.84 a naive t reports on 524
"independent" trades, and its day-blocked p-value is **0.30**. It is not distinguishable from
chance. It was still allowed to trade virtual money, because that is what a virtual book is *for*;
it was never allowed near promotion.

### 3.3 The guardrail the brief cares about most

**No number in this run originated in a model.** `story_lines` records who wrote every sentence;
every LLM-authored line is digit-free once `{{fact:…}}` tokens are stripped — enforced in three
independent places (the Pydantic validator, a database trigger, and the gateway's output contract)
and asserted against the real payload by P1-47. Every `computed_by` names a deterministic component;
a fact claiming `claude-sonnet-5` computed it is rejected **by the database**. Every LLM call is
metered, including narration.

### 3.4 The trigger fired the model, not a clock

`_wake` refuses without a `trigger_id` (P1-34). Two triggers fired, both by the engine:
`scheduled_review` (no market-state series was in its tail, so the observer scheduled the
deterministic scan and only its *results* woke the model) and `observation_threshold` (`exp_0003`'s
book closed ≥30 trades, so the evidence was due a review). The second is the genuinely event-driven
one, and it is what produced the L3 proposal.

### 3.5 Verified by hand

All four endpoints served over HTTP from `KANIDA_PATHFINDER_SOURCE=engine`; the `/loop` story
renders six beats in order with every `{{fact:…}}` resolving; the list leads with the graveyard; the
ledger is ascending by net P&L; all six hash chains verify; an unknown id returns a guarded 404; and
the Postgres source still raises rather than falling back to fixtures.

## 5. Risks — and what the quant audit found

### 5.1 The audit, in full

`dev-quant-auditor` was run adversarially against the engine, the run database and the price
warehouse, and independently recomputed every headline number from source. **It gave a clean bill
on:** the point-in-time seal (proved by seal-invariance — discovery-frame values are bit-identical
to the full frame restricted to the same rows), the exit arithmetic (hand-verified on real trades
including a gap-through-stop that filled 5.5% below the stop level), the availability rule (exact,
not off by one), window separation, the cost arithmetic, the book's cash accounting (reproduced to
the last digit, no double-count), the L3 gate's honesty, and the exact reproducibility of every
published figure. **Its verdict was "do not declare the session done"**, and it was right. Four
findings, all fixed:

| # | Finding | What was wrong | Fix, and what it changed |
|---|---|---|---|
| **1** | **Placebo null mis-specified** | The permutation test drew i.i.d. from the eligible pool, but these signals arrive clustered on market-wide event days. Measured, the i.i.d. null's spread was **0.20 against a correct 0.84 — understated 4×** — which turned p-values of a few percent into zero. | `replay.block_placebo` resamples **days**, and `cluster_robust_t` clusters on the signal date. A naive t of 7.25 becomes **1.63**. Every significance number in the run changed. |
| **2** | **The headline attribution was refuted by the engine's own discarded data** | `loop.py` published "the gap is the tie-break", computed the alternatives three lines later, reduced them to `best`, and threw the comparison away. The audit ran it: the tie-break explains **~4%** of the gap. | The decomposition is computed, **published as facts**, and the claim is conditional on the measured share. Where the share *is* material (`exp_0005`, 87%) the engine still says so. |
| **3** | **The survivorship note described the wrong population** | It said "1,562 symbols, 1 delisting" — a superset. The engine queries `in_nifty500=1 AND is_active=1`: **498 names, 0 delistings, 182 not listed at the discovery window's start.** `is_active` *causes* the perfect survival. | `SURVIVORSHIP_NOTE` rewritten to the filter that actually runs, naming both membership look-ahead and survivorship. |
| **4** | **`total_return_pct` on a replay** | A cumulative sum of 1,702 unit-stake percentages shipped as a **3,866% "return"** with a 2,056% "drawdown". | `None` for `historical_replay` — only a book has capital, so only a book has a return. Asserted by P1-56. |

Three more I fixed before the audit landed, and it independently confirmed two of them: provenance
`as_of` overstating the data by 41 days; a significance failure filed under a false post-mortem
cause; and a `run_book` path that could return a silent empty book.

**Accepted and not fixed, deliberately:**

- **The Bonferroni bar no longer kills at discovery.** With a correct null nothing clears
  `alpha/288`, and a gate that kills everything before out-of-sample defeats the design. Discovery
  is now a *screen* at the naked bar; the family-wise bar and the cluster-t are recorded as
  **advisories** and become **requirements for promotion**. This is a judgement call and it is the
  one I would most like you to push back on. Killing an idea for not being significant on the window
  that chose it treats absence of evidence as evidence of absence; promoting it would be the
  opposite error. It trades virtual money and it is labelled.
- **F9 — the price floor** filtered on back-adjusted prices (look-ahead, but *conservative*: it was
  deleting future winners). Now disabled; the point-in-time turnover filter does the work.
- **F12 — interim marks are gross**, overstating equity between entry and exit by ≤0.42%. Left as
  is, noted here.

### 5.2 The recorded provider is not a live model, and the record says so

14 of 34 story lines were authored by **`claude-opus-5` during this build session** and replayed
from `backend/pathfinder/llm/cassettes/p1_build.json` — not generated at loop time by the model the
routing table names. `llm_calls.model` and `llm_calls.provider` record this truthfully; token counts
are zero because replay spends nothing. Every entry is enforced through the same output contract as
a live completion, and a stale cassette degrades to engine narration rather than lying. **This is
the weakest claim in the session**, and an API key fixes it outright.

### 5.3 Not verified by the audit — stated, not implied

Whether `close` is **dividend**-adjusted was not established. Splits and bonuses are (verified in
both price and volume). If dividends are not, ex-dividend dates produce spurious `gap_down`
firings — which is exposure on `exp_0001`, the scan's top candidate, and essentially nil on the
gap-up experiments. One query against a special-dividend calendar settles it, and it should happen
before any gap-down result is published.

### 5.4 Six experiments, zero survivors, and the temptation that follows

The obvious way to get a green result is to pick the candidate by how it did in the sealed window.
That is the one thing this design exists to prevent, which is why selection is handed a frame that
physically cannot see forward. If a future session produces a promoted experiment, check the seal
first.

### 5.5 The Postgres DDL is still unexecuted

`0001_pathfinder.sql` has now been carried through two sessions without ever running: P1 had no
`psycopg` and would not supply the local instance's password. The laws are proven against the
SQLite mirror instead. `repository.py` is written so porting is implementing one `_Dialect`. Note
`llm_calls` needs a new `provider` column when 0001 is next touched.

### 5.6 The grid is fixed in code, and small

288 candidates over 12 primitives is a narrow search. Widening it is a code change with a diff —
deliberately, so the multiple-testing count cannot drift silently — but Pathfinder currently
explores much less than the name suggests.
