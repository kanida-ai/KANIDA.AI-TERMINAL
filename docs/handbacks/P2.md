## 1. What was built

**`kanida-app/`** — one Expo SDK 57 codebase (expo-router, React Native + `react-native-web`) that ships
**iOS app · Android app · responsive web (desktop web + mobile web)**. The Pathfinder living-loop story,
rendered against the P0 mock.

### The screens

| Route | What it is |
|---|---|
| `/` | **Home.** The Pathfinder card — violet flask, Active badge, the loop's current headline, three counters, chevron. Trader and Investor render as explicitly *Not built*. |
| `/agents` | Agent directory. |
| `/pathfinder/overview` | **Overview.** Today's activity → what woke the model → **the six-beat loop story as a connected thread** → the edge-discovery pipeline → today's experiments (losers first) → what I learned → what I'm testing next → model spend against the daily cap. |
| `/pathfinder/experiments` | **Experiments.** The full list, filterable by stage, rendered in the engine's order (dead first). |
| `/pathfinder/experiment/{id}` | **The full loop story for one hypothesis — the heart.** Reads top to bottom as the loop runs: *I noticed* + the trigger → *I'm testing because* + the rulebook + historical evidence → *the virtual experiment* + the losers-first ledger → *what happened* + history against forward → *what I learned and changed* + the post-mortem + the **L1–L3 change-log** → *what I'll test next* + the condition that will wake it. |
| `/pathfinder/learnings` | **Learnings.** What Pathfinder now believes (statement, level, confidence, n, source experiments, versions changed) + the queue (question, why *now*, the deterministic test planned, **and what is blocked**). |
| `/pathfinder/lab` | **Strategy Lab.** Graduated experiments and their versions. Honest about what it cannot show yet (§4). |
| `/autotrade`, `/insights`, `/profile` | Chrome exists, screens say *Not built*, show nothing. |

Loading skeletons, honest empty states, and an error state that **names the base URL it could not
reach** — which is also the fastest way to tell whether you are pointed at the mock or the engine.

### `{{fact:…}}` resolution — P0's Risk 4, closed

The engine sends narrative with **no numerals in it** plus a `facts[]` array. `src/lib/tokens.ts`
parses `{{fact:…}}` / `{{exp:…}}` / `{{evd:…}}` / `{{ver:…}}`, and `src/components/facts.tsx`
substitutes each figure back into the sentence as a **tappable** number. Tapping opens the number's
provenance: n, sample flag, window, point-in-time `as_of`, data source, universe, cost convention,
and the deterministic component that computed it — closing with *"Computed by the deterministic
engine. The language model reads this number; it never produces one."*

An unresolvable id renders a visible `[missing figure]`, never the raw token and never a silent drop.

### Swapping the mock for the engine is a base-URL change

`EXPO_PUBLIC_API_BASE_URL` is the **only** environment coupling, read in exactly one file
(`src/api/client.ts`). Every screen calls `api.loop()` / `api.experiments()` / `api.experiment(id)` /
`api.learnings()`; nothing else in the app knows a hostname exists. Unset, it infers the Metro host and
port 8010 so scanning the QR on a phone reaches the mock on your laptop with no configuration.
Recorded as **ADR 0005**.

### The honesty rules, in code

`src/lib/honesty.ts` + `src/components/Performance.tsx` are where the non-negotiables physically live:

- **Expectancy is the hero** — the large figure, at the top, always. Win rate appears once, at
  supporting size, under the label "Win rate (supporting)".
- **The 2× slippage gate is shown next to the hero, not buried.** When an edge fails it, a red panel
  says so: *"Whatever the headline number says, this is not tradeable as written."*
- **Every return is paired with its drawdown** — the TypeScript types make a naked return
  unconstructible.
- **Losers first** — the ledger and the list render in the order received. There is **no sort control
  anywhere**, on purpose.
- **Died experiments render exactly like live ones**, with a red badge, their post-mortem and their
  *what we kept*. Never dimmed, collapsed or moved to a secondary surface.
- **n<20 greyed, n<50 flagged** — the server derives the flag, the app renders it. One rule, one owner.
- **No promises, no target prices.** The rulebook shows an invalidation instead, and says so.
- **Every story beat states who wrote it** — "Claude Sonnet 5 · interpreted the engine's numbers" or
  "Deterministic engine · computed, not written".

### Design decisions that extend `docs/FRONTEND_SPEC.md`

All ten are written into that file's new **P2 build record** section. The four worth reading here:

1. **The experiment card's two figures are expectancy, not "return."** The spec asks for "Historical
   return · Virtual return"; CLAUDE.md says expectancy is the hero and no return appears without its
   drawdown. The card keeps the mockup's layout, weight and rhythm — the cumulative return and its
   drawdown sit on the supporting line beneath. Only what the big number *means* changed.
2. **No "average virtual return" anywhere** (the spec's third Overview stat). See §4 — it is a
   contract gap, not an omission.
3. **Inline facts render in neutral emphasis, not green/red.** A fact has no direction: `12.7%` is
   good as a win rate and bad as a drawdown. Colour is reserved for the labelled metrics.
4. **A `+` appears only where it carries information.** Inline, a positive number is unsigned and a
   negative always shows a true minus. Caught reviewing the live render: *"a worst drawdown of
   +12.70%"* reads as a gain.

## 2. How to run it

```bash
# 1. the API — session P0's honest mock
cd backend && uvicorn pathfinder.mock_app:app --port 8010

# 2. the app
cd kanida-app && npm install && npm start
#   w = web · i = iOS · a = Android · or scan the QR in Expo Go
```

Point it at the engine when P1 lands — nothing else changes:

```bash
EXPO_PUBLIC_API_BASE_URL=https://api.kanida.ai npm start
```

Verify:

```bash
cd kanida-app
npm run typecheck                 # tsc --noEmit, app + tests
npm test                          # 15 unit rows (no server needed)
npm run test:contract             # 16 rows against a LIVE server
npm run test:all
npx expo lint
npx expo export --platform all    # iOS + Android + web from this one source
```

  slippage charged.
- **P2-27** — append-only `seq`; L4 human-decided *and* human-approved; L3 states its validation.
- **P2-30** — a 404 returns the guarded error shape with no stack trace or SQL.

**`npm run test:contract` is the acceptance suite for the P1 swap.** Point it at the real engine; if it
passes unchanged, every screen renders honestly against real data with no code change.

### Verified by hand in the browser

Driven at **375 px** and **1440 px**, in **dark and light**, against the live mock:
the Home card; the Overview counters, trigger card, six-beat thread and pipeline; the experiments list
and its filters; **`exp_0007` end to end** (masthead → rulebook → ledger → history-vs-forward →
post-mortem → change-log → next-review); **`exp_0015`** (queued — renders "PROVISIONAL, not yet run"
and "a queued experiment holds no virtual capital" rather than zeros); the Learnings screen; a fact
chip opening its provenance sheet; and `exp_9999` producing the error state with the base URL, code,
HTTP status and request id.

### Two of my own bugs the review caught, both honesty bugs

1. **Fact chips signed every positive percentage**, so the post-mortem read *"a worst drawdown of
   **+12.70%**"* — a loss rendered as a gain. Fixed by the sign policy in decision 4 above, with a
   unit-test row (P2-10) that pins it.
2. **An evidence bundle with no performance block was rendered through a synthesised zero-filled
   block**, printing *"n = 0 closed trades"* for a bundle that has no trade count. That is an invented
   number in a product whose whole claim is that it does not invent numbers. `ProvenanceStrip` now
   takes a `Provenance` and an **optional** `n`, and prints nothing where there is nothing.

I am flagging both because the second one is exactly the failure this product exists to prevent, and I
wrote it.

## 5. Risks

1. **The iOS and Android bundles were never run on a device or simulator.** `expo export --platform all`
   proves all three targets *bundle* from this one source (exit 0), and the web target was driven by
   hand. There is no macOS and no Android SDK on this machine. **First action for whoever picks the app
   up: `npm run ios` / `npm run android`.** Written into `docs/TEST_PLAN.md` § Known gaps.
2. **The mockups are still not in the repo** (§4). This is the one thing in the brief I could not
   satisfy, and it stays open until the images land.
3. **`src/api/types.ts` is a hand-maintained mirror of the contract.** `docs/openapi.yaml` is generated
   from `backend/pathfinder/schemas.py`; the TypeScript is written by hand alongside it. The contract
   tests catch a *semantic* drift (a missing drawdown, an unsorted ledger) but not a purely structural
   rename. Generating the types from the spec — `openapi-typescript` in `scripts/` — would close it,
   and is a small job worth doing before a second consumer exists.
4. **The fixtures are invented and they look real** (P0's Risk 3, inherited). The app makes this
   visible — it renders `computed_by`, the window and the `as_of` on every number — but the screenshots
   this session produced are of *mock* data and should not be shown to anyone as results.
5. **No visual-regression or accessibility automation.** Contrast, focus rings and touch targets were
   designed for and inspected by hand, not asserted. The dark theme is the designed one; light is
   supported and legible, not tuned.
6. **`Intl` on older Android.** Indian digit grouping and the IST date formatting rely on full-ICU
   `Intl`. Hermes on current React Native ships it, but this is the kind of thing that silently
   degrades on an old device — worth a look during the first device run.
7. **No auth, no offline cache, no analytics.** Four read-only public GETs. All three are later slices,
   and none of them changes the shape of what is here.
