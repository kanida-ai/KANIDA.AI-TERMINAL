3.2 Quantity calculation
def calculate_quantity(symbol: str, amount: float, instrument_type: str,
                        expiry_preference: str, broker: BrokerClient) -> int:
    """
    Fetch live LTP from broker at entry time.
    For EQ/MTF/CNC: qty = floor(amount / ltp)
    For FUT: qty = floor(amount / (ltp × lot_size)) × lot_size
    For CE/PE: qty = floor(amount / (premium × lot_size)) × lot_size
    Never returns 0. If amount < 1 lot value: raise InsufficientCapitalError.
    Lot sizes fetched from broker instrument master — never hardcoded.
    """
4. Multi-Broker Router
4.1 Why this exists
The system must support running the same session across multiple brokers simultaneously. Example use cases: 5 stocks on Zerodha (MTF), 5 stocks on Fyers (CNC), options on Upstox. Each broker gets its own profile with its own capital allocation, order type, and stock list.

4.3 Routing logic
class BrokerRouter:
    def route_picks(self, falcon_picks: list[Pick],
                    profiles: list[BrokerProfile]) -> dict[str, list[Pick]]:
        """
        For each broker profile:
          - If profile.symbols is set: use that exact list
          - If profile.rank_range is set: filter falcon_picks by rank
          - If both None: use all falcon_picks up to top_n_stocks
        Returns: {profile_id: [Pick, ...]}
        A symbol CAN appear in multiple broker profiles (same stock, different products).
        Capital accounting is per-profile, not aggregate.
        """

5. Order Execution Engine
5.1 Entry timing — 9:15 AM logic
Backtesting is done at 9:15 AM open price. The live system must match this as closely as possible.

[TABLE]
Order type | When to use | Execution logic | Slippage risk
MARKET (default) | All standard entries | Place market order at exactly entry_time. Accept open price. | Low — 1-3 ticks typical at 9:15
LIMIT | When user wants price control | Place limit at (live_pre_open_price × (1 + limit_offset_pct)). If unfilled in entry_window_seconds: cancel and place MARKET. | None if fills. Miss risk if stock gaps up.

5.2 Instrument-specific order construction
def build_order(symbol: str, qty: int, config: TradingSessionConfig,
                broker: BrokerClient) -> OrderParams:
    if config.instrument_type == "EQ":
        return EQOrder(symbol, qty, config.order_product, config.order_type)
    elif config.instrument_type == "MTF":
        return MTFOrder(symbol, qty)  # product=MTF, always CNC-like hold
    elif config.instrument_type == "FUT":
        contract = broker.get_active_futures(symbol, config.expiry_preference)
        # expiry_preference: "near" = current month, "next" = next month
        lot_size = broker.get_lot_size(contract)
        lots = qty // lot_size
        return FUTOrder(contract, lots, "NRML", config.order_type)
    elif config.instrument_type in ("CE", "PE"):
        chain = broker.get_option_chain(symbol)
        strike = select_atm_strike(chain, config.instrument_type)
        contract = broker.get_option_contract(symbol, strike, config.expiry_preference)
        lot_size = broker.get_lot_size(contract)
        lots = qty // lot_size
        return OptionOrder(contract, lots, "NRML", config.order_type)
5.3 Error handling — mandatory for all order placement
# Every order placement must handle:
# 1. API timeout
async def place_order_with_retry(order, broker, max_retries=3, timeout_ms=2000):
    for attempt in range(max_retries):
        try:
            return await asyncio.wait_for(broker.place_order(order), timeout=timeout_ms/1000)
        except asyncio.TimeoutError:
            log.error(f"Order timeout attempt {attempt+1}: {order.symbol}")
            if attempt == max_retries - 1:
                raise OrderTimeoutError(order)
# 2. Partial fills — detect and handle
def handle_partial_fill(order_id, filled_qty, requested_qty, broker):
    if filled_qty < requested_qty:
        remaining = requested_qty - filled_qty
        # Log partial. Register partial position in registry.
        # Do NOT place another order for remaining unless user config says so.
        log.warning(f"Partial fill: {order_id} filled {filled_qty}/{requested_qty}")
        position_registry.register_partial(order_id, filled_qty)
# 3. Slippage tracking
def record_slippage(symbol, expected_price, actual_price, qty):
    slippage_pct = (actual_price - expected_price) / expected_price * 100
    db.insert("order_slippage", {symbol, expected_price, actual_price, slippage_pct, qty})
    if abs(slippage_pct) > 0.5:  # Alert on > 0.5% slippage
        alert.send(f"High slippage on {symbol}: {slippage_pct:.2f}%")

6.2 Aggregate portfolio PnL — computed every tick
class PortfolioMonitor:
    def compute_gross_return(self, session_id: str) -> float:
        """
        Called every tick (or every 1 second if tick not available).
        gross_return = sum(unrealised_pnl for all OPEN positions) / total_allocated_capital
        This is the number compared against kill_switch_pct.
        """
        positions = db.get_open_positions(session_id)
        total_unrealised = sum(
            (p.ltp - p.avg_price) * p.qty
            for p in positions if p.ltp is not None
        )
        return total_unrealised / self.config.total_allocated_capital

7. Portfolio Kill Switch
7.1 What the kill switch does
When aggregate gross return crosses the configured threshold, the kill switch fires. It overrides everything. No individual stop-losses, no pending orders, no held positions matter at that point. Everything is flattened as fast as possible across all brokers.

[TABLE]
The kill switch is the highest-priority process in the system. When it fires, it cancels all pending orders first, then liquidates all positions. Nothing else runs until all exits are confirmed or timed out.
[/TABLE]

7.2 Kill switch configuration

[TABLE]
Config field | Example value | Meaning
kill_switch_pct | 0.012 | Fire when gross return ≥ +1.2% (profit target)
kill_switch_pct | -0.010 | Fire when gross return ≤ −1.0% (loss limit)
kill_switch_direction | "profit" | Only fire on positive threshold (lock in gains)
kill_switch_direction | "loss" | Only fire on negative threshold (cut losses)
kill_switch_direction | "both" | Fire on either side — use kill_switch_pct as magnitude
kill_switch_enabled | False | Disable entirely — manual exit only
[/TABLE]

7.3 Kill switch execution sequence
class KillSwitchExecutor:
    async def fire(self, session_id: str, trigger_reason: str):
        """Sequence is CRITICAL. Do not reorder."""
        log.critical(f"KILL SWITCH FIRED: {trigger_reason}")
        db.update_session_status(session_id, "KILLING")
        # STEP 1: Cancel all pending orders across all brokers (parallel)
        cancel_tasks = []
        for profile in self.active_broker_profiles:
            pending = await profile.broker.get_pending_orders()
            for order in pending:
                cancel_tasks.append(profile.broker.cancel_order(order.id))
        await asyncio.gather(*cancel_tasks, return_exceptions=True)
        # return_exceptions=True: one broker failure does not stop others
        # STEP 2: Liquidate all open positions across all brokers (parallel)
        exit_tasks = []
        positions = db.get_open_positions(session_id)
        for pos in positions:
            broker = self.get_broker(pos.broker_profile)
            exit_tasks.append(
                broker.place_market_exit(pos.symbol, pos.qty, pos.instrument_type)
            )
        results = await asyncio.gather(*exit_tasks, return_exceptions=True)
        # STEP 3: Handle failures
        for i, result in enumerate(results):
            if isinstance(result, Exception):
                pos = positions[i]
                log.error(f"Exit FAILED for {pos.symbol} on {pos.broker_profile}: {result}")
                alert.send_urgent(f"MANUAL EXIT REQUIRED: {pos.symbol} on {pos.broker_profile}")
                # Mark in DB as EXIT_FAILED — human must act
                db.update_position_status(pos.id, "EXIT_FAILED", str(result))
        # STEP 4: Mark session closed
        db.update_session_status(session_id, "CLOSED")
        db.record_kill_switch_event(session_id, trigger_reason, gross_return)
    def check_threshold(self, gross_return: float) -> str | None:
        """Called every tick. Returns trigger reason or None."""
        if not self.config.kill_switch_enabled:
            return None
        if self.config.kill_switch_direction in ("profit","both"):
            if gross_return >= self.config.kill_switch_pct:
                return f"PROFIT_TARGET gross_return={gross_return:.4f}"
        if self.config.kill_switch_direction in ("loss","both"):
            if gross_return <= -abs(self.config.kill_switch_pct):
                return f"LOSS_LIMIT gross_return={gross_return:.4f}"
        return None

What already exists — do not touch these

[TABLE]
Exit mechanism | What it does | Scope | Status
Trailing Stop Loss | Tracks peak price since entry. If price retraces by stop_trail_pct from the peak, exit that individual position. | Per position (stock-level) | EXISTS — do not touch
Trailing Profit | Locks in profit as price rises. Moves the profit floor up with the price. Exits when price falls back through the floor. | Per position (stock-level) | EXISTS — do not touch
Time-Bound Exit | If a position has been open for N minutes/hours without hitting any other exit, close it at that time. | Per position (stock-level) | EXISTS — do not touch
Day-Bound Exit | Force-close all open positions by a fixed market time (e.g. 3:15 PM IST) regardless of P&L. | Session-level (all positions) | EXISTS — do not touch
[/TABLE]

The one new thing: Kill Switch priority
The portfolio kill switch introduced in the main spec is the only new exit mechanism. It sits above all four existing exits in priority. The interaction rules are:

[TABLE]
Situation | What happens | Rule
Kill switch fires while trailing stop is monitoring a position | Kill switch wins. Cancel the trailing stop monitor. Fire market exit immediately. | Kill switch overrides all per-position exits
Kill switch fires while time-bound exit is pending | Kill switch wins. Do not wait for the time-bound exit. Fire immediately. | Kill switch overrides time-bound exit
Kill switch fires at the same time as day-bound exit | Either fires the market exit. Do not double-exit. Use a position lock to prevent duplicate orders. | First one wins. Lock the position on first exit attempt.
Trailing stop fires on stock A while kill switch is NOT triggered | Trailing stop exits stock A normally. Other positions continue. Kill switch keeps monitoring the remaining portfolio. | Per-position exits are unaffected until kill switch fires
Day-bound exit fires and closes all positions before kill switch threshold is reached | Session ends via day-bound exit. Kill switch never fires (nothing left to exit). | Day-bound exit is the last resort if kill switch threshold was never reached
Kill switch fires and one position is mid-fill from a trailing stop exit | Cancel the partial trailing stop exit order. Place a fresh market exit for the full remaining quantity. | Kill switch must recalculate open quantity before placing exit
[/TABLE]

How to implement the priority — position state machine
Each position must have a status field that prevents duplicate exits. This is the only code change needed in the existing exit layer:
# Add to existing live_positions table (or equivalent in your schema):
# exit_lock: BOOLEAN DEFAULT FALSE
# exit_initiated_by: VARCHAR(30)  -- TRAILING_STOP | TRAILING_PROFIT |
# #                                   TIME_BOUND | DAY_BOUND | KILL_SWITCH | MANUAL
# In every existing exit handler, wrap with this lock check:
def try_exit_position(position_id: str, exit_reason: str, qty: int, broker):
    """
    Single exit gate. Every exit — trailing stop, time-bound, kill switch —
    must go through this function. Never place an exit order directly.
    """
    with db.row_lock(position_id):          # database-level row lock
        pos = db.get_position(position_id)
        if pos.exit_lock:
            log.info(f"Exit blocked: {position_id} already being exited by {pos.exit_initiated_by}")
            return  # another mechanism already claimed this exit
        db.set_exit_lock(position_id, exit_reason)
    # Lock acquired — this mechanism owns the exit
    broker.place_market_exit(pos.symbol, qty, pos.instrument_type)
    db.update_position_status(position_id, "CLOSING", exit_reason)
