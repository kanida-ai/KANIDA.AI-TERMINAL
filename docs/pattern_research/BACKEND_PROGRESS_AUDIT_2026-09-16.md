## Important remaining limitations / documentation drift

1. **Vendor migration is prepared, not completed.** `market_data/vendor15_provider.py` is a configurable REST adapter tested against fixtures. Real symbol IDs, schema, adjustment basis, timestamp semantics, pagination and publication delay still require the actual vendor's specification and live conformance verification. Kite is the operating provider.
2. **Refined statistical results are not in the serving DB.** The report's two-stage two-million-replicate refinement is a sidecar recomputation. Both named candidate cells still have stored 400-replicate `p=.002494`, `q=.8569958467881944`, `discovery_q10=0`, while the report quotes refined q≈.0475. Cards use the stored values; no refinement override was found in serving code.
3. **Baseline-window mismatch is not surfaced by the card transform.** CGPOWER 1H/CDLGAPSIDESIDEWHITE/canonical/long/setup and TTML 4H/canonical_context/long/confirmed have persisted `baseline_window_mismatch=1`, coverage **70.03% / 38.27%**. The card code ignores that flag and `honesty()` says the baseline uses the same window whenever `baseline_status='tested'`. This needs reconciliation before treating those comparisons as reliable release evidence.
4. **An unreviewed clean run is not a released evidence population.** Completion, source repair and compatible detector identity do not substitute for an explicit publication decision.
5. **Live catch-up is principally append-only.** `plan_symbol` starts at `last_stored + 15 minutes` (`ingest.py:186`), so the store can preserve restatements when fetched but the normal loop does not continuously refetch all older candles to discover retroactive vendor corrections. Dedicated repair/refresh remains relevant.
6. **Retention/depth are bounded.** Live daily history starts around 2021; research daily history is deeper through archived payloads. Short weekly series may not satisfy a family's warm-up. Expired/invalidated detection retention is 30 days plus a 200,000 terminated-row cap; this is not unlimited per-instance outcome history.
7. **Storage remains substantial.** Main files at inspection: market15 about **19.5 GB**, expanded research DB **5.3 GB**, outcome DB **38.5 GB**, app research index **162 MB**, scanner cache **510 MB**, excluding WAL files and frozen/raw artifacts. Separation is implemented, but lightweight cloud portability still needs a retention/storage plan.

8. **CAS daily/weekly freshness breaks Discover-to-chart navigation.** The live HINDZINC Rising Wedge daily setup exists as `HINDZINC:1D:CH06:legacy_1.0.1:short`, confirmed and live. The scanner returns it with `current:false` when queried with `live=true&min_trades=0&symbol=HINDZINC&timeframe=1D&pattern_id=CH06`; adding `current=true` removes it. Its correct official daily bar ends `2026-09-16 15:30:00`, confirmed in both chart response and `daily_bars`. HINDZINC's stored session regime is CAS from 2026-08-03. `SymbolCalendarView.session` (`market_scanner/data.py:264`) shortens continuous trading to 15:15; inherited daily and weekly calendar methods also consequently use 15:15. `Scanner.expected_close` (`engine.py:150`) applies that shortened schedule to every timeframe, while `aggregate_market15` explicitly preserves official daily/weekly bars at 15:30 (`data.py:412`). A pure-calendar check at 17 September 09:48 IST returns CAS expected daily `16 September 15:15` and weekly `11 September 15:15`. Thus latest CAS daily/weekly detections are falsely stale. `evidence.display_matches` (`kanida-app/server/kanida_pilot/evidence.py:192`) requests only current matches; `display_match` then cannot resolve the real setup, producing the chart's missing-setup state. This observed failure is not an ID mismatch and occurs before the separate top-500 display limit can matter.
